# 使用说明

## 1. 安装

### Debian / Ubuntu（deb）

```bash
sudo apt install ./waachat_1.0.0_amd64.deb
```

用 `apt install ./文件.deb` 而不是 `dpkg -i`：前者会自动装上缺失的依赖。

### 任意发行版（AppImage）

```bash
chmod +x WaaChat-1.0.0.AppImage
./WaaChat-1.0.0.AppImage
```

AppImage 不需要安装、不需要 `libfuse2`。想集成到应用菜单，可用 [AppImageLauncher](https://github.com/TheAssassin/AppImageLauncher)，或自己放一个 `.desktop` 文件。

### 如果双击没反应（Ubuntu 24.04 及更新）

Ubuntu 从 24.04 起默认限制非特权 user namespace，会破坏 Chromium 的进程沙箱，症状是**双击没反应、终端运行却正常**。

**用 deb 安装：不需要做任何事。** 安装包的 postinst 会自动把配套 profile 装到
`/etc/apparmor.d/waachat` 并加载它。装完直接启动即可。

**用 AppImage：需要手动装一次**（AppImage 没有安装脚本，且挂载路径每次不同）：

```bash
./WaaChat-1.0.0.AppImage --appimage-extract
sudo cp squashfs-root/resources/apparmor/waachat /etc/apparmor.d/
sudo apparmor_parser -r /etc/apparmor.d/waachat
```

> 这份 profile 的形态与 Ubuntu 官方为 VS Code 等应用提供的一致：只放行 user namespace，不改变其它权限。**不要**为了省事在 `.desktop` 里加 `--no-sandbox`。

详见 [`packaging.md`](packaging.md) 第 6 节「AppArmor：两份 profile，职责不同」。

### 托盘图标不显示（GNOME）

需要 AppIndicator 支持：

```bash
sudo apt install gnome-shell-extension-appindicator
```

装完注销再登录。托盘缺失不影响核心功能。

> ⚠️ **没有那个图标时，应用仍然表现得像有托盘**（[ADR-0034](decisions.md#adr-0034)）：窗口依然是"关闭即隐藏"，应用继续在后台保持连接。因为"桌面上到底有没有显示这个图标"**检测不到**（没有任何指示器宿主时 `new Tray()` 依然成功），所以这里没法自动换一种行为。缺扩展时用这两条入口：
>
> - **把窗口叫回来**：再运行一次 `waachat` —— 单实例锁会把已有的那扇聊天窗口调出来。
> - **真正退出**：`Ctrl+Q`（默认菜单提供，不经过托盘）。

## 2. 首次使用

1. 启动应用，等待出现二维码。
2. 手机上打开聊天应用 → **设置** → **已链接的设备** → **链接设备**。
3. 扫码。历史消息会开始同步，同步时间取决于历史量。

> 链接成功后，手机不需要一直在线。但如果手机上把该设备**移除**，本机需要重新扫码。

### 界面与托盘菜单

应用有**三扇窗口**，各管一件事；都由托盘右键菜单打开：

| 窗口 | 打开方式 | 里面有什么 |
|---|---|---|
| 聊天 | 托盘 → 「显示聊天」（再次启动应用也是这个） | 官方网页版界面本身（承载方式正在迁移，见 [`ADR-0043`](decisions.md#adr-0043)） |
| 文件列表 | 托盘 → 「文件列表」 | 你打开过的文件：按文件名搜索、直接打开、在文件夹中显示 |
| 设置 | 托盘 → 「设置」 | 偏好设置（第 5 节）。接管**失效**时你会收到一条系统通知（"接管失效"），平时的状态不再占用界面 —— 见 [ADR-0042](decisions.md#adr-0042) |

三扇窗口都可以随手关掉：**关闭只是隐藏**，应用继续在托盘里待着、保持连接；真正的退出入口是
托盘里的「退出」，`Ctrl+Q` 等价（**没有可见的托盘图标时它就是唯一入口**，见第 1 节 —— 桌面环境
缺 AppIndicator 扩展时就会这样，而这件事我们检测不到）。窗口标题里写着各自的名字
（`WaaChat — 文件列表` / `WaaChat — 设置`），任务栏与窗口列表按它区分。

> 为什么"设置"是独立的一扇窗口：见 [ADR-0025](decisions.md#adr-0025)。那扇窗口原来还挂着"接管状态"标签，现已去掉、改由系统通知告知失效（[ADR-0042](decisions.md#adr-0042)）。

设备槽位是有限的（通常在 4 个左右），注意别把槽位占满。

## 3. 核心行为：点击文件直接打开

这是本应用与网页版的主要差别。

**第一次**打开某个文件：

```
点击  →  自动解密并归档到本地  →  系统默认应用直接弹出
```

**之后**再打开同一个文件：

```
点击  →  读本地归档  →  立即打开（不再走"下载到 ~/Downloads"那一路）
```

> 打开动作本身永远是本地的。**要不要重新联网取一次密文取决于"密文磁盘缓存"**：开启（默认）
> 时连媒体请求都不会发出；把它关掉之后，页面仍会重新取一遍密文（大小等于文件本身，可能命中
> Chromium 自己的 HTTP 缓存），但落盘与打开都走归档。这也是那个开关的主要用途（第 5 节）。

由此带来的几个结果：

| 场景 | 行为 |
|---|---|
| 同一个文件被转发到多个会话 | 只存一份（内容相同即视为同一文件） |
| 原链接在服务端过期 | 归档仍在，照常打开 |
| 想找以前打开过的文件 | 在「文件列表」窗口里按文件名搜索（托盘 → 「文件列表」） |
| 不想让它自动打开 | 在「设置」窗口里改为"只归档，不自动打开" |

**注意**：文件**不会进 `~/Downloads`**，更不会散落在它的根目录里。归档统一收进 `~/Documents/WaaChat_files/` 这一个子目录，而且**文件名就是聊天里那个名字**（`2026年第三季度采购合同.pdf`）—— 可以直接在文件管理器里看、复制、发出去。这是刻意的：`报告 (1).pdf`、`报告 (2).pdf` 那种堆积正是本项目要消灭的行为，同一个文件被发来两次，归档里仍然只有一份（同内容只占一份磁盘）。

## 4. 文件存在哪里

归档的位置**可以改**（默认 `~/Documents/WaaChat_files`，**首次启动会自动创建**，连 `~/Documents` 不存在时也会一并建好），其余几处固定。**删除后果完全不同**（见 [ADR-0008](decisions.md#adr-0008) / [ADR-0018](decisions.md#adr-0018) / [ADR-0023](decisions.md#adr-0023) / [ADR-0032](decisions.md#adr-0032)）：

```
~/Documents/WaaChat_files/            归档：你打开过的文件（位置可在设置里改）
├── 18665597400/                账号那一层（ADR-0039）：页面记下的账号标识
│   └── files/
│       └── 2026-10/            按**归档时间**（你点开它的那一刻）分月份，单层
│           ├── 2026年第三季度采购合同.pdf   文件正文：名字就是聊天里的名字，权限 0400（只读）
│           └── 报价单 (a1b2c3d4).pdf       同一个月内同名但内容不同：名字后面带一小段哈希
├── 2026年第三季度采购合同.pdf   旧版本留下的平面布局：不搬动，照旧能打开、能迁移
└── .index.sqlite              归档索引（含"什么时候打开过什么"）

~/.local/share/waachat/cache/<账号>/<年-月>/   密文缓存（默认开启）：纯派生数据，可随时删除
                                              层级与归档镜像，但根目录独立（不随归档位置移动）

~/.config/waachat/               配置与登录态（Electron 的 userData）
├── settings.json              偏好设置
├── custom-icon.png            自定义应用图标（设置过才有），0600
└── …                          Cookies / Local Storage / IndexedDB —— 登录态在这里

~/.cache/waachat/logs/           日志，可随时删除

~/.local/share/applications/     仅在你换过应用图标之后才会出现
└── io.github.edwinhuish.waachat.desktop   启动器条目覆盖（Icon= 指向上面那张图）
```

| 目录 | 删了会怎样 |
|---|---|
| `~/.config/waachat/` | **需要重新扫码链接设备。不要删。** |
| `~/Documents/WaaChat_files/`（或你自己设的位置） | 你打开过的文件丢失，且若原链接已过期则无法恢复 |
| `~/.local/share/waachat/cache/` | 只影响性能，下次自动重建，随时可删 |
| `~/.cache/waachat/logs/` | 只是丢失排查线索 |
| `~/.config/waachat/custom-icon.png` | 图标回到默认值，其余不受影响（也可以在设置里点「恢复默认」） |
| `…/applications/io.github.edwinhuish.waachat.desktop` | 启动器图标回到默认；下次改图标会重新写入 |

登录态与归档**物理分离**（前者在 `~/.config`，后者在你选的文档目录）是刻意的：这样一来"清理归档"这类功能在文件系统层面就不可能走到登录态，而不是靠实现者记得别传错路径。

**在「设置」窗口里换保存位置时**：应用会先弹一个确认框（写明从哪搬到哪、多少个文件、多大），确认后才开始迁移，过程中显示进度；**取消则一切不变**。迁移把正文与索引一起搬过去，所以新位置的「文件列表」窗口里是完整的历史。

迁移失败时会把已经搬走的文件**放回原位**，界面会明确告诉你回滚成功没有 —— 若提示"部分文件可能仍留在新位置"，请核对两个目录后再继续使用。半成品（`.part-*`）不参与迁移，它们本来就会被清扫掉。

> 归档正文的文件名**就是聊天里的名字**，所以直接翻文件夹就能用；它按**你点开它的那一刻**分进 `2026/10/` 这样的年月目录（[ADR-0037](decisions.md#adr-0037)），因此"最近下载的东西"总在最新的月份目录里。同一个目录内同名但内容不同的文件会在名字后面加一小段哈希（`报价单 (a1b2c3d4).pdf`）—— 去重靠的是内容哈希，不靠名字：同一份内容换个名字发来，磁盘上只会多一个名字、不多占字节；换个**月份**发来则是另一个目录里的同一个文件（硬链接，同样不多占字节）。
>
> ⚠️ 别在文件管理器里手工挪动归档里的文件 —— 索引记着它们的位置，挪过之后会"搜得到但打不开"。旧版本留下的平面布局（正文直接躺在归档目录根下）不会被自动整理进年月目录，两种位置可以长期并存。

### 关于隐私

**归档目录里的文件是解密后的明文**，不受端到端加密保护。它的安全性等于你本机磁盘的安全性。

- 目录权限是 `0700`（仅本人可读），文件 `0400`（**只读**，仅本人可读）。年月子目录（`2026/10/`）同样由本应用创建、同样是 `0700`。目录已存在但权限更宽时，启动时会被收紧。
  只读防的是"就地改内容"：归档是内容寻址的，文件被改写之后索引里那份哈希就对不上了（症状是"搜得到，但打开后不是当初那份"）。
  它**不**妨碍删除或迁移 —— 两者只依赖目录的写权限（见 [ADR-0031](decisions.md#adr-0031)）。
- **不要**把归档目录放进任何云同步盘（Dropbox / OneDrive / iCloud / 坚果云 等）。默认位置 `~/Documents/WaaChat_files` **有可能正落在同步范围里**（有些同步客户端默认就接管 `~/Documents`）—— 如果你的同步盘盖住了它，请**在设置里把保存位置改到同步范围之外**。理由不止是隐私：那会把解密后的明文复制到别处，而且同步客户端通常不保留权限位。
- 共享机器上请开启"退出时清除归档"（见下）。
- 需要更强保护请使用全盘加密，或把归档目录指向加密卷。

## 5. 偏好设置

「设置」窗口里改完**立刻生效**，没有"保存"按钮。例外是标注了「重启后生效」的项 —— 界面上会写明，因为那类开关对应的是会话级的协议注册，在架构上无法热切换。

下面按窗口里的**区域**分组（区域与行序都在 `src/shared/settings-sections.ts`，单测与自检会断言它们）。

**归档**

| 选项 | 默认 | 说明 |
|---|---|---|
| 文件保存位置 | `~/Documents/WaaChat_files` | 点「更改…」选目录 → 确认后**自动迁移**已有归档；取消则存储位置与数据都不变 |
| 归档大小上限 | 不限制 | 归档占用的上限。**淘汰策略尚未实现（计划 M2）**，界面上该项是禁用的 —— 设了值也不会被执行，归档仍会一直增长。状态文案跟着当前值走：只有**设了值**时才标「尚未生效」，「不限制」不标（那本身就是当前配置在照常执行） |
| 点击文件时自动打开 | 开启 | 关闭后只归档，你自己从「文件列表」窗口打开 |
| 退出时清除归档 | 关闭 | 共享机器上建议开启。只清归档，不影响登录态 |

**密文缓存**

| 选项 | 默认 | 说明 |
|---|---|---|
| 密文磁盘缓存 | 开启 | 把聊天文件的密文留在本地，第二次打开同一个文件不再联网（不涉及解密，也不保存密钥）。拨动它**不用重启**：会立刻完成一次转换，全部成功才切换（见下）。为什么默认开启见 [ADR-0028](decisions.md#adr-0028) |
| 密文缓存上限 | 2 GB | 缓存占用的上限，**放在它所管辖的那个开关旁边**（见下）。**容量控制尚未实现（计划 M3）**，界面上该项是禁用的 —— 缓存目前只增不减，也**没有**任何统计告诉用户它现在占了多少 |
| 后台预取文档 | 关闭 | 收到文件消息时预先拉取密文（**预取的就是缓存里的那份**），点开时更快。**尚未实现（计划 M3）** |

**阅读**

| 选项 | 默认 | 说明 |
|---|---|---|
| 禁用 PDF 预览 | 关闭 | 开启后 PDF 不再交给内核阅读器：一律走下载 → 归档 → 系统默认 PDF 阅读器（**不用重启**，立刻生效）；同时挡掉上游预览页的内容。⚠️ **上游的预览面板仍会打开并停在加载态**（那是页面自己的界面，改不了），取文件请用消息上的「下载」—— 会弹一条系统通知提醒。理由与实测见 [ADR-0041](decisions.md#adr-0041) |

**外观与启动**

| 选项 | 默认 | 说明 |
|---|---|---|
| 应用图标 | 默认图标 | 点「选择图片…」换图标（PNG / JPG / ICO）。窗口图标立即生效（X11）、托盘图标通常立即（部分指示器实现下可能要下次启动）；启动器 / 任务栏图标要重新登录桌面。见下 |
| 开机自启 | 关闭 | 登录后自动启动并保持连接 |

> **容量项与它管辖的开关在同一个区域里**：归档大小上限跟在「文件保存位置」后面，密文缓存上限紧跟「密文磁盘缓存」—— 容量没有作用对象时，那行提示是读不懂的（"2 GB"是给谁设的上限？）。区域标题也必须对区域里的每一行都为真，否则用户会按标题去找东西。
>
> 把"没实现的项"标成禁用而不是悄悄留着，是刻意的：一个能改但不起作用的开关，会让用户相信一件不成立的事。见 `ai/CONVENTIONS.md` 第 4 节「降级必须可见」。而那句状态本身也不是写死的：它由当前值算出来，功能落地后会自动变成"超过之后会发生什么"。

### 切换「密文磁盘缓存」

拨动那个开关不是"立刻改一个值"，而是一次**有始有终的转换**（[ADR-0027](decisions.md#adr-0027)）：

1. **没有确认框，也没有进度屏**（[ADR-0028](decisions.md#adr-0028)）：转换通常只是缓存目录内的
   重命名与删除，一瞬间就结束了。开关那一行会在转换期间禁用自己并显示进行态，结束后给出一行结果；
2. 关闭会**清掉**已有缓存（纯派生数据，只影响速度，下次打开会重新下载）；开启只会清掉永远命不中的
   残留，已有的缓存会留着；
3. **全部文件转换成功后**才真正切换，因此不会出现"设置说关了、磁盘上还留着缓存"的中间状态；
4. 任何一步失败（磁盘满、权限、文件被占用）都会**回到切换前的状态**：文件搬回去、设置一个
   字节都不写。界面会分清两种结果 —— "状态未变，缓存文件一个都没少"与"⚠️ 部分文件可能仍留在
   暂存区，请核对"。

> 这个开关**不需要重启**：提交的那一刻协议层就跟着挂上或摘掉了。
> 如果上一次切换被强杀（断电、`kill -9`）打断，下次启动会按**已提交的设置**把它收尾 —— 设置还是
> 老样子就把文件搬回去（回退），设置已经切过去了就把剩下的清掉（收尾）。

### 应用图标

点「选择图片…」，选中一张 PNG / JPG / ICO（WebP、BMP、GIF 也认）。应用会自动**居中裁剪成
正方形**再缩放到 512×512，裁剪结果立刻显示在按钮左边 —— 到这一步它已经生效了。

Linux 下"应用图标"其实是三个落点，生效时机并不一样：

| 落点 | 什么时候能看到 |
|---|---|
| 窗口图标（标题栏、任务切换器） | 立刻。**只在 X11 会话下有效** —— Wayland 下窗口图标由桌面环境按应用标识决定，应用无权改 |
| 托盘图标 | 通常立刻。部分指示器实现（appindicator）下可能要**下次启动**才更新 —— 我们**不**用"重建托盘"去逼它立刻生效：那会引入一个我们无法验证的 GObject 生命周期问题（[ADR-0034](decisions.md#adr-0034)） |
| 启动器 / 任务栏 / Dock 图标 | **要重新登录桌面**（或注销再进来）。桌面环境按应用标识缓存图标，改文件不会立刻反映出来 |

最后一条很容易被读成"改了没用"。不是没改，是桌面还没有重新读它 —— 界面上的提示也写了这一点。

「恢复默认」会删掉自定义图标与那份启动器条目，回到安装时的样子。

失败时会告诉你具体原因（不是图片、太大、磁盘已满、或者启动器里已经有一个**你自己写的**同名
条目），并且**什么都不改** —— 原来的图标仍然在。

> 为什么启动器图标要重新登录才能变、为什么不直接改系统目录：见
> [`decisions.md`](decisions.md) 的 [ADR-0022](decisions.md#adr-0022)。

## 6. 常见问题

### 点文件没反应，还是下载到 `~/Downloads`

接管失效。可能是上游改版。请按[接管失效模板](https://github.com/edwinhuish/waachat/issues/new/choose)提 issue，并附上：

```bash
waachat 2>&1 | grep -iE 'download|capture|cache' | tail -40
```

### 升级之后「文件列表」是空的（归档去哪了）

如果升级前用的是**默认位置**，会看到这个：归档的默认目录名从 `~/Documents/WhatsApp_files`（[ADR-0023](decisions.md#adr-0023)）改成了 `~/Documents/WaaChat_files`（[ADR-0032](decisions.md#adr-0032)）。设置里的"文件保存位置"空着时等于"用默认位置"，于是应用开始用新目录，而**旧目录里的文件仍在原处** —— 只是界面里看不见了。

**不会自动搬**（迁移必须先经你确认，[ADR-0019](decisions.md#adr-0019)）。两条出路：在设置里点「更改…」选回旧目录，或者自己在文件管理器里把文件搬过来。

### 点 PDF 没有出现预览 / 想让 PDF 用系统阅读器打开

**默认就是在应用内预览**（上游自己的预览页），这是「禁用 PDF 预览」关闭时的样子。想改用系统默认
PDF 阅读器，就到设置里打开**「禁用 PDF 预览」**（立刻生效，不用重启）：内核内置的 PDF 阅读器在
Electron 里关不掉（实测见 [ADR-0029](decisions.md#adr-0029)），所以那一项做的是反过来 ——
把 `application/pdf` 一律降级成下载，让文件走归档、交给系统阅读器。

**开启之后你会看到什么**（实测见 [ADR-0041](decisions.md#adr-0041)，与直觉不同，值得先读一眼）：

- 点聊天里的 PDF，**上游那个预览面板仍然会打开，而且会停在加载态**。那个面板是页面自己的界面，
  本应用没有去改它（`INV-1` 已由 [`ADR-0043`](decisions.md#adr-0043) 撤销，所以这现在是**选择**而不是约束：
  改它就得跟着上游的 DOM 结构跑）；面板里那份内容（上游的 viewer SDK）
  被我们挡掉了，于是它一直转圈。这是这一项的**已知代价**，不是"设置没生效"。
- 因此**取文件要走消息上的「下载」**（消息上的下载按钮）：那一步会走接管点 A —— 归档，然后用系统
  默认阅读器打开。每次挡下预览，本应用都会弹一条**系统通知**提醒你这件事。
- 端到端加密意味着 PDF 的明文只存在于页面内存里，本应用**无法替上游触发**那一次下载（[ADR-0029]）。
- 不想看到那个转圈的面板，就把它关掉（[ADR-0030](decisions.md#adr-0030)）—— 关掉之后预览照常工作。

### 打开的是错误的应用 / 是空白

系统的 MIME 关联不对，与本应用无关。用 `xdg-mime` 查一下该类型的默认应用：

```bash
xdg-mime query default application/pdf
```

### 文件为什么是只读的 / 我想改一个文件

归档正文是 `0400`（只读）。原因：归档按内容寻址，索引里记着每份文件的内容哈希；文件被**就地**改一个字节，那份哈希就与内容不再相符 —— 症状是"搜得到，但打开后不是当初那份"，而且没有任何地方会报错。只读把这条不变量交给文件系统，而不是靠你记得别改。

想改一个文件：**复制出去再改**（或在编辑器的"另存为"里存到别处）。只读**不**妨碍删除与迁移 —— 这两件事只依赖目录的写权限，所以随时可以删掉整个归档，也可以在设置里换保存位置（见 [ADR-0031](decisions.md#adr-0031)）。

### 文件名后面多了一段哈希（`报价单 (a1b2c3d4).pdf`）

那是**同名但内容不同**的两份文件：名额先给先到的那份（`报价单.pdf`），后来那份带上自己内容哈希的一小段，因此谁也覆盖不了谁。同一份内容换个名字发来则不会这样 —— 它会在磁盘上多一个名字、共享同一份字节。

> 旧版本（[ADR-0031](decisions.md#adr-0031) 之前）落盘的正文仍是哈希名，本应用**不会**在启动时替它们改名：改名与索引写入没有共同的提交点，为一批"多数人并没有"的数据引入半途失败路径不值得。它们照常可以打开、搜索、迁移，被打开时会把只读权限补上。

### 资源加载不出来 / 日志里一堆 `handshake failed`

那行日志来自 Chromium 的网络栈：

```
ERROR:net/socket/ssl_client_socket_impl.cc:962] handshake failed; returned -1, SSL error code 1, net_error -101
```

`net_error -101` 是 `ERR_CONNECTION_RESET`：TCP 连接在 TLS 握手过程中被**重置** —— 不是证书问题，也不是"协议谈不拢"，是连接本身没了。常见来源有三种：链路自己抖动（Wi-Fi 切换、休眠唤醒）、中间的防火墙/代理在按域名重置连接、运营商侧的干预。

本应用能做的只有两件事（[ADR-0033](decisions.md#adr-0033)）：把拦截来的请求**发回它自己的会话**（不再多维护一套连接池与 cookie 罐子），以及在**连接层失败**时对它自己发起的请求做有限重试（只重试 `GET`/`HEAD`，最多 3 次尝试，间隔约 0.3 / 0.9 秒）。

看日志就能分出两种情况：

```bash
waachat 2>&1 | grep -iE 'retrying|gave up' | tail -20
```

- 只有 `capture: retrying after a connection failure` —— 网络在抖，但**重试救回来了**，可以不管。
- 出现 `capture: gave up on a flaky connection`（带 `host` 与 `net::ERR_…`）—— 连试几次都不通。**如果它反复出现且集中在同一个 host，那是这条链路被阻断或极不稳定，改这个应用没有用**：用代理 / VPN，或者换网络。

> 页面的 websocket（`wss://`）与不经过 https 的流量不在这条路径上，它们由上游页面自己负责。
>
> 想试命令行开关的话：`waachat --disable-quic`（如果日志里出现的是 `quic_*` 一类错误，说明是 UDP 被干扰）或 `waachat --disable-http2`。这些**不是**默认行为 —— 它们会实打实地牺牲性能，只有确认是协议栈被干扰时才值得试。

### 日志里的 `GLib-GObject: ... has no handler with id ...`

```
ERROR:content/browser/browser_main_loop.cc:279] GLib-GObject: ../../../gobject/gsignal.c:2723:
  instance '0xd4c000cbb10' has no handler with id '8345'
```

这**不是**本应用的报错。它来自 GLib 自己（`gsignal.c`），意思是"有人要断开一个在这对象上已经不存在的信号处理器"。发出它的是加载进**同一个进程**的某个 GTK 模块或指示器库 —— 常见的有 Ubuntu 的 GTK 模块（`colorreload-gtk-module` / `window-decorations-gtk-module`）、`appmenu` 模块，以及托盘用的 `libayatana-appindicator`。本应用的代码是 JavaScript，不碰 GObject 的信号 id。

实测（[ADR-0034](decisions.md#adr-0034)）：按生产里的用法逐条跑过 —— 托盘只建一次 + `setImage()` 刷新、窗口建一次后隐藏、另建几扇窗口再销毁、最后销毁托盘与窗口 —— **一条都不会产生**。想确认自己环境里加载了什么：

```bash
echo "GTK_MODULES=$GTK_MODULES"
grep -h gtk-modules ~/.config/gtk-3.0/settings.ini /etc/gtk-3.0/settings.ini 2>/dev/null
dpkg -l | grep -Ei 'appindicator|appmenu'
```

**什么时候才该担心它**：它出现时窗口与托盘通常是好的（能开关、点得到菜单）。只有当它**同时**伴随图标不显示、菜单点不动、窗口关不掉这类症状时，才值得单独报一个 issue。

> 想把它从输出里去掉：`waachat --log-level=3`（只留致命错误）。**不推荐** —— 它会把网络握手失败、`capture: giving up on a flaky connection` 这些真正有用的诊断一并盖掉（见上面「资源加载不出来」那条）。

### 启动时的 `'--ozone-platform=wayland' is not compatible with Vulkan`

```
ERROR:ui/ozone/platform/wayland/gpu/wayland_surface_factory.cc:249]
  '--ozone-platform=wayland' is not compatible with Vulkan.
  Consider switching to '--ozone-platform=x11' or disabling Vulkan
```

这是 Chromium 的 **GPU 进程**在说话，而且它说的是一件具体的事：**Wayland 上没实现 Vulkan 的 surface**（`CreateViewSurface()` 是 `NOTIMPLEMENTED()`）。它每次启动都会出现，是因为 Chromium 里有一条**默认开启**的路 —— 「WebGPU 跑在原生 Vulkan 上、再经 GL 互操作上屏」—— 会去要一个原生 Vulkan 实现。所以它既不是"你的显卡有问题"，也不是 Vulkan 初始化失败。

本应用在**走 Wayland 时**把这条路关掉（`--use-webgpu-adapter=opengles`，见 [ADR-0038](decisions.md#adr-0038)），所以默认情况你不会再看到它。四条边界：

- X11 会话下**一个开关都不动**（那边的 Vulkan 可能是好的）；
- 你自己传的 `--disable-features=…` 会被**合并**而不是覆盖；
- 你要是**显式**传了 `--enable-features=Vulkan`，我们就不插手；
- 你要是**自己指定了 WebGPU 后端**（`--use-webgpu-adapter=…`，例如 `vulkan`），我们同样不动它 —— **那行 ERROR 会回来**，代价就是你要的"原生 Vulkan 上的 WebGPU"。

```bash
waachat 2>&1 | grep -i vulkan   # 应当看不到那行 ERROR（我们的开关日志在 stdout 上）
```

> 如果同一行出现在**别的**应用里（浏览器、别的 Electron 应用），那与本应用无关 —— 那是它们自己的进程。
>
> 想自己验证这不是显卡问题：`waachat --ozone-platform=x11`（Chromium 给的另一条建议）。我们**不**默认这么做 —— 它会把原生 Wayland 一起丢掉（窗口图标靠 `app_id`、缩放、分数缩放）。
>
> 为什么代价是"WebGPU 换后端"：Chrome 那行报错的来源那条路，只有 `--use-webgpu-adapter=opengles` 能关掉（它不是可以用 `--disable-features` 关的 feature），而它换来的是 WebGPU 在 Wayland 上改走 ANGLE/GL —— 仍是 GPU 加速，只是不走原生 Vulkan。

### 通话 / 频道 / 社区用不了

这些功能由上游网页版提供。网页版有什么就有什么，网页版没有的本应用也不会有。通话还需要在系统设置里允许应用使用麦克风与摄像头。

> ⚠️ 但**权限**这一层是我们自己把关的：只有通知、麦克风/摄像头、写剪贴板、全屏、以及"存储不要被淘汰"这五项会被放行，其余一律拒绝 —— 见下一条。

### 某个功能点了没反应 / 日志里的 `permission denied`

本应用对**权限**是白名单把关的（[ADR-0035](decisions.md#adr-0035)），因此上游申请的某些权限会被我们**拒绝**，日志里留下一条：

```
WARN permission denied {"permission":"geolocation","fromUpstream":true}
```

放行的只有这五项（都只对上游源生效）：

| 权限 | 对应功能 |
|---|---|
| `notifications` | 页面自己的消息通知 |
| `media` | 麦克风 / 摄像头（通话、语音消息） |
| `clipboard-sanitized-write` | "复制"按钮 |
| `fullscreen` | 通话与媒体查看器的全屏 |
| `persistent-storage` | "这份存储不要被淘汰" —— 保住登录态与消息库 |

其余全拒，包括 `clipboard-read`（静默读剪贴板）、`geolocation`（位置）、`display-capture`（屏幕捕获）、`midi*`、`openExternal` 等等。

**如果某个上游功能因此不可用**（例如通话里的"共享屏幕"点了没反应），把日志里那条 `permission denied` 贴出来就行 —— 那正是我们需要的证据，ADR-0035 里列了每一项的取证方式。**不要**为了"先跑起来"去改白名单：那一行是安全边界（`docs/security.md` T5），加它需要一次决策。

### 怎么彻底卸载

```bash
# deb
sudo apt remove --purge waachat

# 手动清除数据（注意：会删除归档与登录态，不可恢复）
rm -rf ~/.config/waachat ~/.cache/waachat ~/.local/share/waachat
# 归档目录（若在设置里改过位置，换成你设的那个）
rm -rf ~/Documents/WaaChat_files
# 换过应用图标的话，还有一份用户级启动器条目（系统装的那份由 apt remove 收走）
rm -f ~/.local/share/applications/io.github.edwinhuish.waachat.desktop
```
