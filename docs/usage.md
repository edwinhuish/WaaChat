# 使用说明

## 1. 安装

### Debian / Ubuntu（deb）

```bash
sudo apt install ./waachat_1.0.0_amd64.deb
```

用 `apt install ./文件.deb` 而不是 `dpkg -i`：前者会自动装上缺失的依赖。

### 任意发行版（AppImage）

```bash
chmod +x WaaChat-1.0.0.AppImage
./WaaChat-1.0.0.AppImage
```

AppImage 不需要安装、不需要 `libfuse2`。想集成到应用菜单，可用 [AppImageLauncher](https://github.com/TheAssassin/AppImageLauncher)，或自己放一个 `.desktop` 文件。

### 如果双击没反应（Ubuntu 24.04 及更新）

Ubuntu 从 24.04 起默认限制非特权 user namespace，会破坏 Chromium 的进程沙箱，症状是**双击没反应、终端运行却正常**。

**用 deb 安装：不需要做任何事。** 安装包的 postinst 会自动把配套 profile 装到
`/etc/apparmor.d/waachat` 并加载它。装完直接启动即可。

**用 AppImage：需要手动装一次**（AppImage 没有安装脚本，且挂载路径每次不同）：

```bash
./WaaChat-1.0.0.AppImage --appimage-extract
sudo cp squashfs-root/resources/apparmor/waachat /etc/apparmor.d/
sudo apparmor_parser -r /etc/apparmor.d/waachat
```

> 这份 profile 的形态与 Ubuntu 官方为 VS Code 等应用提供的一致：只放行 user namespace，不改变其它权限。**不要**为了省事在 `.desktop` 里加 `--no-sandbox`。

详见 [`packaging.md`](packaging.md) 第 6 节「AppArmor：两份 profile，职责不同」。

### 托盘图标不显示（GNOME）

需要 AppIndicator 支持：

```bash
sudo apt install gnome-shell-extension-appindicator
```

装完注销再登录。托盘缺失不影响核心功能。

## 2. 首次使用

1. 启动应用，等待出现二维码。
2. 手机上打开聊天应用 → **设置** → **已链接的设备** → **链接设备**。
3. 扫码。历史消息会开始同步，同步时间取决于历史量。

> 链接成功后，手机不需要一直在线。但如果手机上把该设备**移除**，本机需要重新扫码。

### 界面与托盘菜单

应用有**三扇窗口**，各管一件事；都由托盘右键菜单打开：

| 窗口 | 打开方式 | 里面有什么 |
|---|---|---|
| 聊天 | 托盘 → 「显示聊天」（再次启动应用也是这个） | 官方网页版界面本身，逐字节一致 |
| 文件列表 | 托盘 → 「文件列表」 | 你打开过的文件：按文件名搜索、直接打开、在文件夹中显示 |
| 设置 | 托盘 → 「设置」 | 偏好设置（第 5 节），以及**接管状态** —— 那几行字告诉你"文件是被本应用接管的、还是退回给了浏览器" |

三扇窗口都可以随手关掉：**关闭只是隐藏**，应用继续在托盘里待着、保持连接；只有托盘里的
「退出」才是真的退出。窗口标题里写着各自的名字（`WaaChat — 文件列表` / `WaaChat — 设置`），
任务栏与窗口列表按它区分。

> 为什么"设置"是独立的一扇窗口、接管状态为什么跟在它旁边：见 [ADR-0025](decisions.md#adr-0025)。

设备槽位是有限的（通常在 4 个左右），注意别把槽位占满。

## 3. 核心行为：点击文件直接打开

这是本应用与网页版的主要差别。

**第一次**打开某个文件：

```
点击  →  自动解密并归档到本地  →  系统默认应用直接弹出
```

**之后**再打开同一个文件：

```
点击  →  读本地归档  →  立即打开（不再走"下载到 ~/Downloads"那一路）
```

> 打开动作本身永远是本地的。**要不要重新联网取一次密文取决于"密文磁盘缓存"**：开启时连
> 媒体请求都不会发出；默认关闭时，页面仍会重新取一遍密文（大小等于文件本身，可能命中
> Chromium 自己的 HTTP 缓存），但落盘与打开都走归档。这也是那个开关的主要用途（第 5 节）。

由此带来的几个结果：

| 场景 | 行为 |
|---|---|
| 同一个文件被转发到多个会话 | 只存一份（内容相同即视为同一文件） |
| 原链接在服务端过期 | 归档仍在，照常打开 |
| 想找以前打开过的文件 | 在「文件列表」窗口里按文件名搜索（托盘 → 「文件列表」） |
| 不想让它自动打开 | 在「设置」窗口里改为"只归档，不自动打开" |

**注意**：文件**不会进 `~/Downloads`**，更不会散落在它的根目录里。归档统一收进 `~/Documents/WhatsApp_files/` 这一个子目录，正文以内容哈希命名（去重靠它），要看原始文件名就用「文件列表」窗口。这是刻意的 —— `报告 (1).pdf`、`报告 (2).pdf` 那种堆积正是本项目要消灭的行为。

## 4. 文件存在哪里

归档的位置**可以改**（默认 `~/Documents/WhatsApp_files`，**首次启动会自动创建**，连 `~/Documents` 不存在时也会一并建好），其余几处固定。**删除后果完全不同**（见 [ADR-0008](decisions.md#adr-0008) / [ADR-0018](decisions.md#adr-0018) / [ADR-0023](decisions.md#adr-0023)）：

```
~/Documents/WhatsApp_files/            归档：你打开过的文件（位置可在设置里改）
├── <sha256>                   文件正文，文件名为内容哈希
├── .open/                     临时的、带原始文件名的硬链接，用于交给系统应用打开
└── .index.sqlite              归档索引（含"什么时候打开过什么"）

~/.local/share/waachat/cache/    密文缓存（默认不开启）：纯派生数据，可随时删除

~/.config/waachat/               配置与登录态（Electron 的 userData）
├── settings.json              偏好设置
├── custom-icon.png            自定义应用图标（设置过才有），0600
└── …                          Cookies / Local Storage / IndexedDB —— 登录态在这里

~/.cache/waachat/logs/           日志，可随时删除

~/.local/share/applications/     仅在你换过应用图标之后才会出现
└── io.github.edwinhuish.waachat.desktop   启动器条目覆盖（Icon= 指向上面那张图）
```

| 目录 | 删了会怎样 |
|---|---|
| `~/.config/waachat/` | **需要重新扫码链接设备。不要删。** |
| `~/Documents/WhatsApp_files/`（或你自己设的位置） | 你打开过的文件丢失，且若原链接已过期则无法恢复 |
| `~/.local/share/waachat/cache/` | 只影响性能，下次自动重建，随时可删 |
| `~/.cache/waachat/logs/` | 只是丢失排查线索 |
| `~/.config/waachat/custom-icon.png` | 图标回到默认值，其余不受影响（也可以在设置里点「恢复默认」） |
| `…/applications/io.github.edwinhuish.waachat.desktop` | 启动器图标回到默认；下次改图标会重新写入 |

登录态与归档**物理分离**（前者在 `~/.config`，后者在你选的文档目录）是刻意的：这样一来"清理归档"这类功能在文件系统层面就不可能走到登录态，而不是靠实现者记得别传错路径。

**在「设置」窗口里换保存位置时**：应用会先弹一个确认框（写明从哪搬到哪、多少个文件、多大），确认后才开始迁移，过程中显示进度；**取消则一切不变**。迁移把正文与索引一起搬过去，所以新位置的「文件列表」窗口里是完整的历史。

迁移失败时会把已经搬走的文件**放回原位**，界面会明确告诉你回滚成功没有 —— 若提示"部分文件可能仍留在新位置"，请核对两个目录后再继续使用。派生文件（打开用的硬链接、半成品）不参与迁移，它们本来就会重建。

> 归档正文的文件名是内容哈希（去重靠它）。要看原始文件名，用「文件列表」窗口 —— 那里有「在文件夹中显示」。

### 关于隐私

**归档目录里的文件是解密后的明文**，不受端到端加密保护。它的安全性等于你本机磁盘的安全性。

- 目录权限是 `0700`（仅本人可读），文件 `0600`。目录已存在但权限更宽时，启动时会被收紧。
- **不要**把归档目录放进任何云同步盘（Dropbox / OneDrive / iCloud / 坚果云 等）。默认位置 `~/Documents/WhatsApp_files` **有可能正落在同步范围里**（有些同步客户端默认就接管 `~/Documents`）—— 如果你的同步盘盖住了它，请**在设置里把保存位置改到同步范围之外**。理由不止是隐私：那会把解密后的明文复制到别处，而且同步客户端通常不保留权限位。
- 共享机器上请开启"退出时清除归档"（见下）。
- 需要更强保护请使用全盘加密，或把归档目录指向加密卷。

## 5. 偏好设置

「设置」窗口里改完**立刻生效**，没有"保存"按钮。例外是标注了「重启后生效」的项 —— 界面上会写明，因为那类开关对应的是会话级的协议注册，在架构上无法热切换。

| 选项 | 默认 | 说明 |
|---|---|---|
| 应用图标 | 默认图标 | 点「选择图片…」换图标（PNG / JPG / ICO）。窗口与托盘立即生效；启动器 / 任务栏图标要重新登录桌面。见下 |
| 文件保存位置 | `~/Documents/WhatsApp_files` | 点「更改…」选目录 → 确认后**自动迁移**已有归档；取消则存储位置与数据都不变 |
| 点击文件时自动打开 | 开启 | 关闭后只归档，你自己从「文件列表」窗口打开 |
| 密文磁盘缓存 | 关闭 | 第二次打开同一个文件不再联网。拨动它**不用重启**：会先弹确认框，然后进入维护界面显示转换进度，全部成功才切换（见下）。默认关闭的理由见 [ADR-0026](decisions.md#adr-0026) |
| 后台预取文档 | 关闭 | 收到文件消息时预先拉取密文，点开时更快。**尚未实现（计划 M3）** |
| 退出时清除归档 | 关闭 | 共享机器上建议开启。只清归档，不影响登录态 |
| 开机自启 | 关闭 | 登录后自动启动并保持连接 |
| 归档大小上限 | 不限制 | **尚未生效（淘汰策略计划 M2）**，界面上该项是禁用的 |
| 密文缓存上限 | 2 GiB | **尚未生效（计划 M3）**，界面上该项是禁用的 |

> 把"没实现的项"标成禁用而不是悄悄留着，是刻意的：一个能改但不起作用的开关，会让用户相信一件不成立的事。见 `ai/CONVENTIONS.md` 第 4 节「降级必须可见」。

### 切换「密文磁盘缓存」

拨动那个开关不是"立刻改一个值"，而是一次**有始有终的转换**：

1. 先弹确认框，写明这次要处理多少个文件、多大 —— 以及关闭会**清掉**已有缓存（开启只是清掉
   永远命不中的残留，已有的缓存会留着）；
2. 确认后，设置窗口整个换成**维护界面**，显示目标状态与转换进度；
3. **全部文件转换成功后**才真正切换，因此不会出现"设置说关了、磁盘上还留着缓存"的中间状态；
4. 任何一步失败（磁盘满、权限、文件被占用）都会**回到切换前的状态**：文件搬回去、设置一个
   字节都不写。界面会分清两种结果 —— "状态未变，缓存文件一个都没少"与"⚠️ 部分文件可能仍留在
   暂存区，请核对"；
5. 转换期间**不能进行其他操作**：维护界面里根本没有别的控件，这是结构上的事实。

> 这个开关**不需要重启**：提交的那一刻协议层就跟着挂上或摘掉了（[ADR-0027](decisions.md#adr-0027)）。
> 如果上一次切换被强杀（断电、`kill -9`）打断，下次启动会按**已提交的设置**把它收尾 —— 设置还是
> 老样子就把文件搬回去（回退），设置已经切过去了就把剩下的清掉（收尾）。

### 应用图标

点「选择图片…」，选中一张 PNG / JPG / ICO（WebP、BMP、GIF 也认）。应用会自动**居中裁剪成
正方形**再缩放到 512×512，裁剪结果立刻显示在按钮左边 —— 到这一步它已经生效了。

Linux 下"应用图标"其实是三个落点，生效时机并不一样：

| 落点 | 什么时候能看到 |
|---|---|
| 窗口图标（标题栏、任务切换器） | 立刻。**只在 X11 会话下有效** —— Wayland 下窗口图标由桌面环境按应用标识决定，应用无权改 |
| 托盘图标 | 立刻 |
| 启动器 / 任务栏 / Dock 图标 | **要重新登录桌面**（或注销再进来）。桌面环境按应用标识缓存图标，改文件不会立刻反映出来 |

最后一条很容易被读成"改了没用"。不是没改，是桌面还没有重新读它 —— 界面上的提示也写了这一点。

「恢复默认」会删掉自定义图标与那份启动器条目，回到安装时的样子。

失败时会告诉你具体原因（不是图片、太大、磁盘已满、或者启动器里已经有一个**你自己写的**同名
条目），并且**什么都不改** —— 原来的图标仍然在。

> 为什么启动器图标要重新登录才能变、为什么不直接改系统目录：见
> [`decisions.md`](decisions.md) 的 [ADR-0022](decisions.md#adr-0022)。

## 6. 常见问题

### 点文件没反应，还是下载到 `~/Downloads`

接管失效。可能是上游改版。请按[接管失效模板](https://github.com/edwinhuish/waachat/issues/new/choose)提 issue，并附上：

```bash
waachat 2>&1 | grep -iE 'download|capture|cache' | tail -40
```

### 打开的是错误的应用 / 是空白

系统的 MIME 关联不对，与本应用无关。用 `xdg-mime` 查一下该类型的默认应用：

```bash
xdg-mime query default application/pdf
```

### 「浏览器不受支持」

上游的检测变化。请提 issue 并附上系统信息。

### 二维码扫不出来

检查手机与电脑的**网络是否可用**（不需要在同一个网络），以及手机上的相机权限。

### 通话 / 频道 / 社区用不了

这些功能由上游网页版提供。网页版有什么就有什么，网页版没有的本应用也不会有。通话还需要在系统设置里允许应用使用麦克风与摄像头。

### 怎么彻底卸载

```bash
# deb
sudo apt remove --purge waachat

# 手动清除数据（注意：会删除归档与登录态，不可恢复）
rm -rf ~/.config/waachat ~/.cache/waachat ~/.local/share/waachat
# 归档目录（若在设置里改过位置，换成你设的那个）
rm -rf ~/Documents/WhatsApp_files
# 换过应用图标的话，还有一份用户级启动器条目（系统装的那份由 apt remove 收走）
rm -f ~/.local/share/applications/io.github.edwinhuish.waachat.desktop
```

## 7. 安全与风险提示

使用非官方客户端可能违反服务条款，存在账号被限制的风险。本应用通过"不注入页面脚本、不重实现协议、不自动化收发"把风险压到最低，但不为零。

**开始使用前请读 [`DISCLAIMER.md`](../DISCLAIMER.md)。**
