# 威胁模型与实现对策

根目录的 [`SECURITY.md`](../SECURITY.md) 是对外的**报告流程与边界声明**；本文是对内的**实现依据**。
改动任何落盘路径、IPC 通道、权限白名单或日志内容之前，先读这里。

---

## 1. 信任边界

```
不可信                          │  可信（有权限）
────────────────────────────────┼──────────────────────────────
远程网页内容                     │  Electron 主进程
（随时可能变化、可能被投毒）      │  （独占文件系统与系统调用）
                                │
远程 → 主进程的通道              │  本地渲染进程
只有"事件被观察"这一个方向       │  （自有代码，但仍不直连文件系统）
                                │
                                │  preload 桥
                                │  （白名单、只读）
```

**核心命题**：远程世界可以**被观察**，但不能**发起动作**。

## 2. 资产与保护目标

| 资产 | 位置 | 泄露后果 | 保护手段 |
|---|---|---|---|
| 设备登录凭据 | 会话分区（`~/.config/waachat/`；命名实例在 `~/.config/waachat-<实例名>/`） | 他人可无感读取全部会话，无需手机确认 | 目录权限；**绝不提供清除入口**（ADR-0008）；回源请求发在**同一个分区会话**里（ADR-0033）—— 换到别的会话会让响应的 `Set-Cookie` 落进另一个罐子，登录态因此长期陈旧 |
| 解密后的媒体明文 | 归档目录（默认 `~/Documents/WaaChat_files`，可在设置里改）及其 `<账号>/<会话ID>/files/` 子目录 | 通信内容泄露，且不受端到端加密保护 | 目录 `0700`（账号与会话目录同样由我们创建并收紧，见 ADR-0039 / ADR-0052 / ADR-0055；归档目录已存在但更宽时启动会收紧，见 ADR-0018）、文件 `0400`（只读：归档是内容寻址的，就地改写会让索引里的哈希与内容不再相符；顺带满足"仅本人可读"，见 ADR-0031）；不写日志；可选退出时清除 |
| 归档索引 | `<归档目录>/.index.sqlite` | 泄露"谁在何时传过什么文件"这类元数据 | 同目录权限（索引一整个归档一棵，不在账号目录里，见 ADR-0039） |
| 账号标识（目录名） | 归档与缓存的第一层目录名 | 只泄露"这台机器上有哪个账号的归档"，不含内容 | 只从页面写下的 WID / `wa_ul` cookie 里取，**不碰凭据**（`wa_web_access_token` 就在旁边那条 cookie 上）；净化后只留 `[a-z0-9._-]`（`paths.ts`）；不进日志（INVARIANTS G-3） |
| 会话标识（目录名） | 归档的第二层目录名（`<账号>/<会话ID>/files/`） | 泄露"这个归档里与**谁**有往来"（对端号码 / 群 ID 会出现在目录名上），不含内容 | 与归档目录同一道权限（`0700`）；会话ID 取自页面模型的 `msg.id.remote`（ADR-0055），净化后只留 `[A-Za-z0-9._@-]`（`@` 是标识的一部分，见该 ADR）；不进日志（INVARIANTS G-3） |
| 密文缓存 | `cache/<账号>/<年-月>/`（默认开启，见 ADR-0028） | 危害较低（仍是密文），但可被长期留存分析 | 可随时删除；不参与任何"永久保留"承诺；关掉它时会立刻清空（`capture/cache-files.ts`；启动对账是兜底），失败或中断会回退（ADR-0027）。根目录**独立于归档**（ADR-0008 / ADR-0039） |
| IPC 通道 | 运行期 | 越权触发本地动作 | 通道白名单 + 来源校验 |
| 自定义应用图标 | `~/.config/waachat/custom-icon.png` | **不敏感**（用户自己挑的一张图片），影响面只有外观 | 文件 `0600`；读不出来就删掉并回到默认图标（ADR-0022） |
| 用户级启动器条目 | `~/.local/share/applications/<appId>.desktop` | 不敏感；被改写只影响启动器里的显示 | 只在带 `X-WaaChat-Managed=true` 标记时才写、才删，否则报错放弃（ADR-0022） |

**多实例**（[ADR-0062](decisions.md#adr-0062)）把上表里**每一行**都按实例复制一份：一个实例 = 一份
登录凭据 + 一份归档 + 一份缓存 + 一份设置。这条事实必须写下来，因为它是这张表里"设备登录凭据"那一行的
量变：本机会同时存在 N 份凭据，**每一份都能无需手机确认地读取那个账号的全部会话**。

因此有一条边界要说得非常清楚：**实例名不是安全边界。** 它只是一段目录名（用来避免两个实例互相覆盖），
既不做权限隔离，也不做加密 —— 所有实例的数据都在同一位用户的 `0700` 目录下。它防的是**误操作**，不是
"同机的另一个用户"，更不是"本机已被攻破"（后者本来就在"明确不防的"一栏里）。

`cache/` 里除了密文正文，还为每条正文存一份 `.meta.json`（`capture/protocol.ts`）：其中只有
**响应头白名单**（`capture/headers.ts`，见 ADR-0016）—— 目的是回放时让响应语义与回源一致。
白名单是显式列举而非黑名单，正是因为 `set-cookie` 这类凭据一旦漏进去，就与上表"仍是密文"
的声明冲突（`headers.ts` 的模块注释记着这条理由）。

**更换保存位置**（ADR-0019）时：目标目录会被创建或收紧为 `0700`；跨文件系统的迁移是
"复制到临时名 → 删除源"，因此那一小段时间里明文**同时存在**于两个位置，两处都必须是
`0700`。迁移失败会回滚，但回滚只做搬运、不删数据 —— 宁可留下两份，也不替用户删掉
可能是唯一副本的文件。

**更换应用图标**（ADR-0022）新增两处写入，都比归档轻：`~/.config/waachat/custom-icon.png`（`0600`）
与上面那份用户级启动器条目。解码与裁剪发生在渲染进程，但**送进主进程的只有 PNG 字节**：落盘位置、
文件名与权限全由主进程决定，主进程还会用 `nativeImage` 自己再解一次，确认它确实是一张 512×512 的图。
因此 T2 的判据（"路径必须由主进程产生"）没有被削弱 —— 界面连一个路径都构造不出来。

**拼写检查的词典**（[ADR-0061](decisions.md#adr-0061)）是唯一一处**由我们主动向第三方发起**的请求：内核按需从
默认的下载源（Google 托管的 CDN，取 `<语言码>.bdic`）下载词典，而请求发在承载登录态的**那个分区**里 ——
也就是这台机器上"与上游之外的第二条外联路径"。它不携带任何会话内容（只是一个静态文件名），但这条事实
必须写下来，因为两件事只有在这里才说得清：

- **关掉「拼写检查」这个开关，这个请求就不会发生** —— 那个开关同时是"不要下载词典"的开关；
- 默认下载源**刻意不改**：自己指定一个我们无法验证的来源，只是把"第三方"换成"未知的第三方"。要换源可以走
  `session.setSpellCheckerDictionaryDownloadURL()`，那需要一次独立的评估。

顺带一条与排查有关的：开启密文缓存时，会话级的 `protocol.handle('https')` 会接住该分区里的**所有** https
请求（[ADR-0015](decisions.md#adr-0015)），词典请求因此会走一遍直通 —— 日志里能看到，别把它当成缓存的问题。

**明确不防的**：已取得本机用户权限的攻击者、root、内存取证、被植入的恶意软件、物理接触。
归档目录的权限防的是**同机其他用户**与**粗心的同步工具**，不是防这些。
需要更强保护时应依赖全盘加密或把目录放在加密卷 —— 那是用户的选择，不是本项目的承诺。

## 3. threat 清单

### T1 · 远程内容通过注入通道触达本地能力

**最严重的一类。**

- 触发条件：有人为了"方便"让 preload 直连页面世界，或暴露一个"能执行本地操作"的 IPC 方法给页面。
- 后果：远程页面（或被投毒的上游资源）可以读写用户文件系统、发起任意本地操作。
- 对策：
  - [INV-1](../ai/INVARIANTS.md) 仍禁止注入类 API，并由 ESLint 强制；它有一处**只读元数据例外**
    （[ADR-0057](decisions.md#adr-0057)：`capture/download.ts` 与 `dev-probe.ts` 两处，行内声明）。
    ⚠️ 它此前还有第二条例外 ——"按用户显式选择写下上游自己那条语言偏好 cookie"
    （[ADR-0065](decisions.md#adr-0065)）—— **已由 [ADR-0066](decisions.md#adr-0066) 撤销**：
    界面语言由账号决定，那条 cookie 会被页面改回去。因此今天**没有任何往页面存储里写东西的口子**
    （`pnpm run selfcheck` 第 19 节有一条负向断言守着这一点）。
    因此 T1 靠的是下面三条对策，外加"只读例外只读且取值不回传页面"这条纪律。
  - preload 遵循**单向**原则：只允许"主进程推数据 / 渲染进程读数据"，不提供"页面 → 本地副作用"的调用。
  - 评审 preload 改动时只问一个问题：**这会不会给远程内容带来一个新的本地副作用？** 会就拒。
  - 主进程侧的通道注册必须校验 `event.senderFrame`，拒绝来自远程页面的调用。

### T2 · IPC 通道被本地渲染进程越权调用

- 触发条件：渲染进程按"通道名 + 任意参数"直接驱动主进程的操作（如"删除任意路径"）。
- 后果：渲染进程一旦被 XSS 或第三方脚本影响，即可操作任意文件。
- 对策：
  - 通道**按语义设计**，不按参数设计。不做 `fs:readAny(path)` 这种通用通道，只做 `archive:open(jobId)`。
  - 所有路径参数必须是**主进程自己产生的标识符**，不能是渲染进程传进来的路径字符串。
  - 提交类通道连参数都尽量不要：`appicon:set` 收的是**值**（PNG 字节）而不是路径，
    位置由主进程自己拼（ADR-0022）。"能传值"与"能传能力"的区别就是这一条的分界。

### T3 · 符号链接与临时文件竞态

- 触发条件：归档目录可被其他进程写入；临时文件使用可预测的名字。
- 后果：写到非预期位置，或本地提权（若应用以更高权限运行）。
- 对策：临时文件使用随机名；最终写入用 `rename` 而非跟随链接的写操作；不跟随归档目录内的符号链接。

### T4 · 日志与崩溃信息泄露敏感内容

- 触发条件：为便于调试把文件名、完整路径、会话名写进日志。
- 后果：日志被同步到云端或被他人读到，等于泄露通信内容与社交关系。
- 对策（**强制**）：
  - 日志中**不得**出现：媒体文件名全文、会话名、消息内容、完整绝对路径中的用户名部分、任何 token。
  - 允许出现：内容哈希前缀、MIME 类型、字节数、相对目录名。
  - 崩溃报告同理。默认关闭自动上报。

### T5 · 权限白名单过宽

- 触发条件：为了"少出问题"直接允许所有权限请求。
- 后果：任何来源的内容都能取用摄像头 / 麦克风 / 通知。
- 对策：权限按来源与类型**双向白名单**（落点在 `src/main/permissions.ts` —— 一个不导入 electron 的纯模块，因此单测与离线自检都能断言它），默认拒绝其余一切。当前放行的**类型**恰好五项，每一项都有理由：
  - `notifications`：页面自己的消息通知
  - `media`：麦克风 / 摄像头（通话与语音消息）
  - `clipboard-sanitized-write`：把文本写进剪贴板。**不含** `clipboard-read` —— DOM 的 `paste` 事件不需要它，需要它的是 `navigator.clipboard.read*`，那才是"静默读用户剪贴板"
  - `fullscreen`：通话与媒体查看器
  - `persistent-storage`："这份存储不要被淘汰"。它不授予任何能力，只影响 Chromium 对本分区里该源自己数据的淘汰策略 —— 而那里存着登录态与消息库，拒绝它可能换来一次重新扫码（[ADR-0035](decisions.md#adr-0035)）

  来源判据是 **origin 精确比对**（`shared/upstream.ts` 的 `isUpstreamOrigin`），不是前缀匹配：`https://web.whatsapp.com@evil.com/` 这类输入能以前缀的形式骗过 `startsWith`，后果是把摄像头交给一个第三方页面。**加一项必须带证据**：ADR-0035 里有一张取证清单（哪些权限对应上游的哪个功能、症状是什么、怎么从日志取证）。

### T6 · 供应链

- 触发条件：依赖被投毒，或 CI 权限过大导致可发布恶意产物。
- 对策：
  - CI 的 `GITHUB_TOKEN` 权限最小化（`contents: read`），只有发布工作流需要 `write`。
  - 依赖更新走 Dependabot，**原生依赖与 Electron 主版本升级需要人工评审并跑 `pnpm run verify`**（见 `dependabot.yml` 里的 ignore 规则）。
  - 发布产物附 SHA-256；发布工作流同时归档产物。

### T7 · 用户误解归档的加密属性

- 触发条件：用户以为"端到端加密"覆盖了本地归档。
- 后果：把归档目录放进同步盘，实质泄露全部通信文件。
- 对策：`usage.md` 与首次运行的提示中必须明确说明；`DISCLAIMER.md` 第 3 节是对外承诺。

## 4. 与合规的关系

安全与合规在本项目里是同一件事的两面：

- "不注入"（INV-1）既是合规要求，也是 T1 的根治手段；它的两条例外 —— **只读元数据**
  （[ADR-0057](decisions.md#adr-0057)）与**按用户显式选择写下上游自己那条语言偏好 cookie**
  （[ADR-0065](decisions.md#adr-0065)）—— 不改变这条判断：前者只读、取值不回传页面，后者只碰
  上游自己域上的一条偏好、不夹带脚本，T1 仍主要靠 preload 设计自己守住（见 T1 的对策）。
- 不经手加密（INV-3）使"我们自己的加密实现有缺陷"这一整类问题不存在 —— **这一条仍然成立**，且现在由
  ESLint 的 `cryptoGuards` 与 `pnpm run selfcheck` 第 15 节强制。
- 不重实现传输协议（INV-2）由 ESLint 的 `projectGuards` 强制：禁用 puppeteer 家族 / `whatsapp-web.js` /
  `wwebjs-electron` 与 `*/baileys` 等协议库 —— 协议与加解密仍由官方网页版代码承担。

因此[硬约束](../ai/INVARIANTS.md)的每一次松动都**同时**是安全评审的议题，必须走 ADR。
